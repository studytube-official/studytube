# Problem-free content plan

抜け落ちチェック問題は既存のCUE MAP Shortsを使う。このファイルは、それ以外の投稿企画を扱う。

## Series A: 保存しただけ

目的: マイリスト整理の必要性を認識させる。

1. `あとで見る、何本たまってる？`
2. `保存した勉強動画を二度と見ない理由`
3. `英語と数学が同じ保存欄にある人へ`
4. `今日見る3本だけのリストを作る`

基本構成:

```text
0-2秒   悩み
2-7秒   散らかった保存状態
7-13秒  ManaCueの教科・単元・マイリスト
13-16秒 見ただけを、解けるに。
```

## Series B: 見たのに説明できない

目的: ティーチバックの価値を伝える。問題そのものは出さない。

1. `動画を閉じた直後、何を学んだか1文で言える？`
2. `ノートをきれいに写すより、30秒説明する`
3. `AIに答えを聞くのではなく、理解の穴を聞く`
4. `分かったつもりを見つける一番短い方法`

見せる画面:

- 「学びを説明」
- 理解できている点
- 補うとよい点
- 次に考える質問

「AIが動画を見て採点する」と誤認させない。

## Series C: 3日後

目的: 復習カードと再訪理由を伝える。

1. `今日分かっても、3日後に出なければもったいない`
2. `復習日を自分で決めない勉強法`
3. `覚えた→7日後、忘れた→明日`
4. `保存ではなく、次に思い出す日まで決める`

## Series D: Real workflow

目的: 機能一覧ではなく、1回の利用体験を見せる。

1. `数学の動画を探して、苦手リストへ入れるまで`
2. `動画を見終わってから30秒でやること`
3. `スマホで保存、PCで続きから学ぶ`
4. `今日の復習を1枚だけ終わらせる`

## Series E: Build in public

目的: 小規模プロダクトへの信頼と参加感を作る。

1. `受験生の「見ただけ」を減らすために作っています`
2. `届いた要望を1つ直しました`
3. `AIに送らないもの：字幕・動画・音声`
4. `次に追加するなら、どの機能？`
